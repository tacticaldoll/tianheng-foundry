# Authority Model

| Artifact | Authority |
|---|---|
| Conversation or prose | Evidence of intent |
| Boundary Card | Admitted analysis |
| Generated diff | Candidate law |
| Passing violating and clean proofs | Verified candidate |
| Human-reviewed Constitution change | Accepted law |
| Markdown/JSON rendering | Generated projection |
| Tianheng report | Observation evidence |
| Project decision or commit body | Provenance |

The critical transition is:

```text
VerifiedCandidate --human review--> AcceptedLaw
```

No skill, test, renderer, or clean check substitutes for that review.

## Existing Law

An accepted law blocks ordinary generation from changing itself. A request that needs a different
boundary enters an amendment workflow explicitly; failure pressure is never implicit authority to
weaken the reaction.

## Prose

Live structural prose may dissolve after accepted code and a fresh projection carry the same
claim. History, process, judgment, and API explanation keep their own authority surfaces. Partial
reaction coverage narrows prose; it does not erase the unobserved remainder.
