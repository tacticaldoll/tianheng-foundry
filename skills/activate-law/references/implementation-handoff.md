# Implementation Handoff

Activation feeds an existing coding workflow; it does not replace one.

## Handoff Contract

Pass forward:

- requested outcome and Cargo scope;
- direct and adjacent active boundaries with exact reasons;
- uncovered effects;
- predicted dependency, semantic, runtime, and workspace impacts;
- authority files that remain read-only; and
- the project-native post-change Tianheng command.

Do not pause for confirmation when the user's original request already authorizes implementation.

## During Implementation

The coding workflow should:

- preserve each active reason, not merely avoid known finding strings;
- revisit the Active Law Set when the touch set expands;
- keep uncovered effects visible without inventing policy; and
- leave constitution, baseline, and projection source unchanged unless separately routed.

## Post-change Reaction

Run the same project-native check with structured output and preserve its exit status:

- exit `0`: inspect warnings, baselines, stale entries, and coverage before reporting;
- exit `1`: use `repair-drift` with the actual report;
- exit `2`: resolve reaction validity rather than changing architecture;
- explicit law delta: use `amend-law`.

A pre-change Active Law Set is orientation. The post-change reaction is the binding verification.
