# Migration And Projection

An amendment may require product movement, law movement, or both. Keep their authorities visible.

## Sequencing

### Tighten

When current product code would violate the candidate:

1. preserve accepted-state evidence;
2. add the candidate proof fixture;
3. migrate product code toward the requested intent;
4. apply the boundary amendment;
5. prove the new violation and clean precision cases.

Do not baseline newly forbidden product code by default.

### Loosen Or Remove

1. preserve a witness that fails under accepted law;
2. apply only the authorized law delta;
3. prove the same witness is now clean;
4. prove adjacent retained protection still reacts;
5. migrate product code only when separately requested.

### Retarget

Make old-target disposition and new-target activation visible in the same candidate. Avoid an
intermediate state where neither target is governed.

### Reason Correction

Keep target, rule, parameters, depth, severity, baseline, and finding identities unchanged.
Regenerate projection and compare reaction outcomes.

## Baselines

Baseline changes require their own explicit decision. If authorized, report which current facts are
accepted temporarily, why they are not silently forgiven, and what later trigger removes them.

## Projection

Regenerate through the adopter's declared command after law source changes. Never hand-edit the
projection. A fresh projection is necessary but not sufficient: reaction proofs still decide
whether the amendment has the intended semantics.
