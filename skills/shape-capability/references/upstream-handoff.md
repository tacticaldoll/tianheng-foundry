# Upstream Handoff

Foundry carries adopter evidence; Tianheng owns observation capabilities and public API.

## Default Handoff

Produce a self-contained pressure report containing:

- adopter authority and concrete affected code;
- exact supported version searched;
- nearest existing recipe and mismatch;
- observation and reaction contracts;
- fixture matrix;
- feasibility and limitations; and
- compatibility/public-surface implications.

Do not open an issue or edit another repository by default.

## Persisting In A Tianheng Checkout

Only on explicit request:

1. read Tianheng's current `PROJECT.md`, self-law projection, relevant specs, and contributor
   workflow;
2. route the pressure into its required explore/propose mechanism;
3. preserve the adopter as evidence without importing adopter-specific policy as universal policy;
4. let Tianheng maintainers decide dimension ownership, naming, API, compatibility, and acceptance.

Capability shaping does not authorize implementation. A proposal artifact is not a public API, and
an upstream test sketch is not an observation.

## External Actions

Creating a remote issue, pull request, release, or publication requires separate explicit approval.
Never submit adopter code, private paths, or confidential architecture prose upstream without
authorization.
